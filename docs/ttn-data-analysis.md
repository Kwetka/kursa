# Анализ: ТТН (реализация) vs данные программы

Шаблон: **Товарно-транспортная накладная**, форма установлена постановлением Министерства финансов
Республики Беларусь от 30.06.2016 № 58 (по образцу `ТТН_4691381.docx`).
Программа: складской учёт (WPF + SQL Server), валюта BYN.

Ниже — сопоставление каждого реквизита шаблона с текущей моделью данных
(`Warehouse.Core/Models/Entities.cs`, `Warehouse.Core/Data/Schema.sql`).

Текущие сущности программы:

| Сущность | Поля |
|---|---|
| Product (товар) | Name, Unit (ед. изм.), PurchasePrice, SalePrice |
| Warehouse (склад) | Name, Address, ManagerName, ManagerContact |
| Counterparty (контрагент) | Name, IsSupplier (поставщик/покупатель) |
| User (пользователь) | Login, FullName, Role |
| StockOperation (операция) | OccurredAt (дата), Kind (приход/реализация/перемещение), **один** ProductId + Quantity, FromWarehouseId, CounterpartyId, Comment, UserId |

---

## 1. Шапка накладной

| Реквизит ТТН | В программе? | Источник / что добавить |
|---|---|---|
| Номер ТТН | ✅ Есть | Номер операции реализации (`StockOperations.Id`) или номер нового «документа реализации». |
| Дата ТТН | ✅ Есть | `OccurredAt` (назначается SQL Server при проведении; ввод задним числом не предусмотрен — дата ТТН = дата реализации). |
| Серия ФП | ➖ Некритично | Серия типографского бланка («ФП 1») — артефакт печатной формы. Можно опустить или хранить константой в шаблоне печати. |
| УНП грузоотправителя | ❌ Нет | Нет сведений о собственной организации (см. блок 2). |
| УНП грузополучателя | ❌ Нет | У контрагента нет УНП. |
| УНП заказчика перевозки (плательщика) | ❌ Нет | Нет ни УНП, ни самой сущности «заказчик перевозки». |

## 2. Стороны (наименование, адрес)

| Реквизит ТТН | В программе? | Источник / что добавить |
|---|---|---|
| Грузоотправитель | ⚠️ Частично | Есть `Warehouse.Name` + `Warehouse.Address`, но это **склад**, а не организация: нет юридического наименования («ООО "…"») и реквизитов организации. Нужен справочник/настройка «Моя организация» (наименование юрлица, УНП, адрес) либо доп. поля у склада. |
| Грузополучатель | ⚠️ Частично | Есть `Counterparty.Name` (покупатель), но **нет адреса и УНП**. В шаблоне покупатель указан вместе с адресом — поля нужно добавить. |
| Заказчик автомобильной перевозки (плательщик) | ❌ Нет | Отдельная сторона. Часто совпадает с покупателем; можно решать переключателем «плательщик = покупатель» и хранить только отличие, когда оно есть. |

## 3. Транспортный блок

| Реквизит ТТН | В программе? | Источник / что добавить |
|---|---|---|
| Автомобиль (марка, гос. номер) | ❌ Нет | Справочник «Транспортные средства» (марка + госномер) или ручной ввод при формировании ТТН. |
| Прицеп (марка, гос. номер) | ❌ Нет | То же, поле необязательное. |
| Водитель (ФИО) | ❌ Нет | Поле в ТТН или справочник водителей (перевозчика). |
| К путевому листу № | ❌ Нет | Одно строковое/числовое поле ТТН. |
| Перевозчик (организация) | ❌ Нет | В образце прямо не указан (только авто/водитель), но в полной форме раздела II присутствует. Если свои доставки — можно взять из «Моей организации». |

## 4. Условия отпуска

| Реквизит ТТН | В программе? | Источник / что добавить |
|---|---|---|
| Пункт погрузки (адрес) | ✅ Есть | `Warehouse.Address` склада, с которого списан товар (`FromWarehouseId`). |
| Пункт разгрузки (адрес) | ❌ Нет | Адрес покупателя (новое поле `Counterparty.Address`) + возможность указать иную точку доставки в самой ТТН. |
| Основание отпуска (документ: № и дата) | ❌ Нет | В образце — «Счёт № СС000525 от 03.04.2023». Счетов/заказов в программе нет. Варианты: (а) простое текстовое поле «основание» в ТТН; (б) полноценные документы «Счёт покупателю» (значительно больше работы); (в) автоподстановка «Реализация № X от даты». |

## 5. I. Товарный раздел (табличная часть)

| Колонка ТТН | В программе? | Источник / что добавить |
|---|---|---|
| № п/п | ✅ Есть | Порядковый номер строки при формировании. |
| Наименование товара | ✅ Есть | `Product.Name`. |
| Ед. изм. | ✅ Есть | `Product.Unit`. |
| Количество | ✅ Есть | `StockOperations.Quantity` (до 3 знаков). |
| Цена, руб. коп. | ✅ Есть | `Product.SalePrice` (BYN, 2 знака). |
| Стоимость, руб. коп. | ✅ Есть | Вычисляется: количество × цена. |
| Итого по разделу | ✅ Есть | Вычисляется суммированием строк. |
| Ставка НДС, % | ❌ Нет | В программе нет понятия НДС. Нужно: ставка как настройка (в РБ 20 %) и решение, что такое `SalePrice`: цена без НДС (НДС сверху) или цена с НДС (НДС выделяется расчётным путём, как в образце: ставка 16,3587 %). |
| Сумма НДС, руб. коп. | ❌ Нет | Вычисляется из ставки — после решения по предыдущей строке. |
| Стоимость с НДС, руб. коп. | ❌ Нет | Вычисляется. |
| Кол-во грузовых мест | ❌ Нет | Нужно поле «мест» у товара (или у строки ТТН, ручной ввод). |
| Масса груза, т | ❌ Нет | Нужно поле «вес единицы, кг/т» у товара; итог считается автоматически. |
| Примечание (в образце: розн. цена, скидка) | ⚠️ Частично | Есть `Comment` операции, но скидок/розничных цен в программе нет — либо не заполнять, либо добавить понятие «скидка на строку». |
| Строка «Транспортные услуги» | ❌ Нет | Услуги как позиция документа не поддерживаются (только товары со склада). Можно добавить строку доставки с ценой, если нужно. |

## Итог сопоставления

**Уже есть (ТТН можно заполнить сразу):** номер и дата, грузоотправитель (как склад + адрес),
пункт погрузки, весь «костяк» товарного раздела (наименование, ед. изм., количество, цена,
стоимость), итоги, примечание-комментарий.

**Есть, но неполно:** грузополучатель (только имя покупателя — нет адреса и УНП),
основание отпуска (нет документа-счёта).

**Отсутствует полностью:**
1. Реквизиты собственной организации (юрнаименование, УНП, адрес).
2. УНП и адрес контрагента-покупателя.
3. Заказчик автомобильной перевозки (плательщик).
4. Транспорт: автомобиль, прицеп, водитель, путевой лист.
5. НДС: ставка, суммы, стоимость с НДС.
6. Логистика товаров: грузовые места, масса груза.
7. Документ-основание (счёт) и скидки.

## Варианты внедрения (для выбора целесообразности)

| Вариант | Что даёт | Затраты | Комментарий |
|---|---|---|---|
| **A. Минимум (без изменений БД)** | ТТН с номером/датой, грузоотправителем (склад), покупателем (имя), таблицей товаров, пунктом погрузки, итогами | Низкие | Печатная форма уже возможна; реквизиты вроде УНП будут пустыми/ручными. |
| **B. Реквизиты покупателя** | Поля `Counterparty`: УНП, адрес, телефон | Низкие | Закрывает «Грузополучатель», «Пункт разгрузки», УНП грузополучателя. |
| **C. Профиль «Моя организация»** | Настройка: юрнаименование, УНП, адрес, подписант | Низкие | Закрывает шапку грузоотправителя. |
| **D. Транспортный блок** | Справочник авто/водителей или ручной ввод в ТТН; путевой лист | Средние | Нужен, если ТТН передаётся перевозчику (3–4-й экземпляры). |
| **E. НДС** | Ставка-настройка, суммы НДС, «стоимость с НДС» | Средние | Ключевое решение: цена с НДС или без. Влияет на отчёты и остатки. |
| **F. Логистика товара** | Поля товара: мест в единице, вес единицы | Средние | Автоматическое заполнение «Кол-во мест» и «Масса груза». |
| **G. Счета/основания и скидки** | Документ «Счёт», скидки на строки | Высокие | Самое дорогое; вместо счёта можно текстовое поле «основание». |

## Замечания по архитектуре

- Операция реализации сейчас **однотоварная** (`ProductId`, `Quantity` — скалярные поля).
  ТТН — многострочный документ. Либо вводить сущность «Документ реализации» с позициями,
  либо формировать одну ТТН из группы операций (один покупатель + один склад + период/день).
- Дата операции назначается SQL Server при проведении, задним числом не вводится —
  дата ТТН всегда будет текущей датой проведения.
- `SalePrice` — строго положительная цена без какого-либо НДС/скидок; введение НДС
  затронет справочник товаров, отчёты (суммы остатков) и печатные формы.
- Единица измерения товара после первой операции неизменяема — колонка «Ед. изм.»
  в ТТН будет всегда согласованной с историей.

## Статус реализации (схема БД версии 3)

Реализованы варианты B–G. Ниже показано, где хранятся данные каждого элемента ТТН и кто их вводит.

| Элемент ТТН | Где хранится | Кто заполняет |
|---|---|---|
| УНП, наименование и адрес грузоотправителя (своя организация) | `OrganizationProfile` → снимок в `StockDocuments.Shipper*` | Администратор, «Моя организация» |
| УНП, наименование и адрес грузополучателя (покупатель) | `Counterparties.Unp/Address` → снимок в `StockDocuments.Consignee*` | Менеджер продаж (покупатели), кладовщик (поставщики) |
| Заказчик перевозки (плательщик) и его УНП | `StockDocuments.PayerName/PayerUnp` | Автор документа (подставляется покупатель или своя организация) |
| Номер и дата ТТН | `StockDocuments.Number`, `DocumentDate` (для прихода) или `OccurredAt` | Автор документа |
| Автомобиль, прицеп, водитель, путевой лист | `StockDocuments.Vehicle/Trailer/Driver/WaybillNumber` | Автор документа (есть подсказки из прежних документов) |
| Основание отпуска | `StockDocuments.Basis` (по умолчанию — `Counterparties.Contract`) | Автор документа |
| Пункты погрузки и разгрузки | `StockDocuments.LoadingPoint/UnloadingPoint` (по умолчанию — адрес склада и адрес разгрузки покупателя) | Автор документа |
| Графы 1–6: № п/п, наименование, единица, количество, цена, стоимость | `StockOperations` (позиции документа: `Quantity`, `Price`) | Автор документа |
| Графы 7–9: ставка НДС, сумма НДС, стоимость с НДС | `StockOperations.VatRate` (по умолчанию — `Products.VatRate`); суммы рассчитываются (НДС сверху) | Кладовщик задаёт ставку товара, автор документа может изменить |
| Графы 10–11: количество грузовых мест, масса груза | `StockOperations.CargoPlaces/CargoMassKg` (по умолчанию из `Products.UnitsPerPlace/UnitMassKg`) | Кладовщик (карточка товара), автор документа |
| Графа 12: примечание и скидка | `StockOperations.Comment`, `DiscountPercent` | Автор документа |
| Итоги, суммы прописью | Рассчитываются (`Warehouse.Core/Services/Ttn.cs`) | — |
| «Отпуск разрешил», «Сдал грузоотправитель» | `OrganizationProfile.ReleaseAllowedBy` → `StockDocuments.ReleaseAllowedBy/HandedOverBy` | Администратор задаёт значение по умолчанию; автор документа |

Раздел II «Погрузочно-разгрузочные операции», доверенность, пломбы и подписи программа не заполняет: на печатной форме для них оставлены пустые строки.
