# Склад: управление запасами и анализ оборачиваемости

Учебное приложение для Windows: интерфейс **WPF**, база данных **Microsoft SQL Server** (в том числе SQL Server Express / LocalDB). Валюта цен и стоимостных отчётов — **белорусский рубль, BYN**. Пересчёт валют не выполняется.

## Что необходимо установить

- Windows и Visual Studio 2022 с компонентом «Разработка классических приложений .NET».
- .NET 9 SDK. Это та же основная версия .NET, на которой работал исходный проект.
- Доступный экземпляр Microsoft SQL Server **2017 или новее** (совместимость базы не ниже 140). Для одного компьютера подойдёт SQL Server Express LocalDB; для нескольких компьютеров нужен доступный им экземпляр SQL Server и соответствующие права.
- Доступ к NuGet для восстановления пакетов при первой сборке.
- Для просмотра и правки накладных — Microsoft Word или другой редактор DOCX, например LibreOffice Writer.

LocalDB не является частью репозитория и может быть не установлен вместе с Visual Studio. Его можно добавить в Visual Studio Installer как отдельный компонент или установить SQL Server Express LocalDB. Подробности — в [документации Microsoft](https://learn.microsoft.com/ru-ru/sql/database-engine/configure-windows/sql-server-express-localdb?view=sql-server-ver17).

## Запуск в Visual Studio

1. Откройте `kursa.sln`. Если Visual Studio предложит перезагрузить изменившееся решение, согласитесь.
2. Убедитесь, что стартовый проект — **kursa** (в обозревателе решений: правой кнопкой по проекту → «Назначить запускаемым проектом»).
3. Дождитесь восстановления NuGet-пакетов, затем выполните сборку и запустите приложение клавишей **F5**.
4. При первом запуске откроется окно подключения к SQL Server. Для обычного LocalDB проверьте:
   - сервер: `(localdb)\MSSQLLocalDB`;
   - база данных: `WarehouseCourse`;
   - способ входа: **Windows**;
   - флажок доверия сертификату можно оставить включённым для локального экземпляра.
5. Нажмите **«Подключить и сохранить»**. Если базы ещё нет и у пользователя есть право `CREATE DATABASE`, приложение создаст её. В новой или выделенной пустой базе создаются таблицы и учебные пользователи. Если права на создание базы нет, администратор должен заранее создать отдельную пустую базу и дать пользователю права на создание таблиц и работу с ними.
6. Войдите в приложение, например `admin / admin`, затем смените пароль кнопкой в верхней панели.

Для существующего SQL Server Express сервер может называться `.\SQLEXPRESS`; для удалённого сервера укажите его имя или адрес и предоставленные администратором данные. Поддерживаются аутентификация Windows и логин SQL Server. Для удалённого сервера рекомендуется использовать проверяемый сертификат и снять флажок «Доверять сертификату сервера».

Если LocalDB установлен, его экземпляры можно посмотреть в терминале Windows командой `sqllocaldb info`, а запустить стандартный экземпляр — командой `sqllocaldb start MSSQLLocalDB`. Если команда или экземпляр отсутствует, сначала установите/настройте LocalDB.

Настройки подключения сохраняются в `%LOCALAPPDATA%\WarehouseCourse\connection.dat`, зашифрованные Windows DPAPI для текущей учётной записи Windows. В Git строка подключения и пароль не записываются. Повторно открыть настройки можно кнопкой **«Настроить подключение SQL Server»** на окне входа. Файл настроек **не является резервной копией базы**.

## Учётные записи и права

Начальные пользователи создаются **только при первоначальном создании схемы**:

| Логин | Начальный пароль | Роль |
|---|---|---|
| `admin` | `admin` | Администратор |
| `manager` | `123` | Менеджер |
| `store` | `123` | Кладовщик |

Пароли хранятся как PBKDF2-хеши с индивидуальной солью. Это учебные учётные записи с известными начальными паролями — **смените их сразу**. Для новых паролей требуется 8–200 символов.

| Роль | Разрешённые изменения в приложении |
|---|---|
| **Администратор** | Все справочники, реквизиты организации и контрагентов, все складские операции и реквизиты документов; управление учётными записями и аналитика. |
| **Менеджер** | Только просмотр складов, остатков, операций и справочников, оборачиваемость и отчёты. Данные и операции не изменяет. |
| **Кладовщик** | Добавление, изменение и удаление товаров, в том числе массы единицы и упаковки; многотоварные приход и перемещение. Продажи не проводит, организацию, склады и контрагентов не изменяет. |
| **Менеджер продаж** | Состав и цены реализации, скидки, НДС и данные перевозки. Выбирает получателя и плательщика из карточек контрагентов или организацию как плательщика; справочные реквизиты исправляет администратор. Не проводит приход или перемещение. |

Просмотр доступных справочников, остатков, операций и журнала не означает право изменения. Доступ к аналитике и отчётам — у администратора и обычного менеджера. Кнопки запрещённых действий отключены, а при каждом изменении репозиторий дополнительно заново проверяет актуальную роль в БД; смена роли или удаление аккаунта блокирует последующие изменения и в уже открытой сессии.

**Менеджера продаж нужно создать:** войдите администратором → вкладка «Пользователи» → «Добавить» → роль «Менеджер продаж» → задайте логин, ФИО и пароль. При редактировании можно сменить роль, логин, ФИО или задать новый пароль; пустые поля нового пароля сохраняют прежний пароль. Самого себя удалить или понизить в роли нельзя, последний активный администратор защищён от удаления и понижения. Удаление блокирует вход, но сохраняет автора прежних операций. Логин удалённой учётной записи повторно не используется.

Роли ограничивают действия **через приложение**, но не заменяют самостоятельную настройку прав SQL Server: пользователи приложения используют настроенное подключение к БД. Прямой доступ к таблицам в обход приложения обходит эти проверки. Проект не следует считать готовой к промышленной эксплуатации системой безопасности.

## Обновление существующей базы

Перед обновлением сделайте и проверьте резервную копию SQL Server. Для миграции подключению нужны права `ALTER` на таблицы и `CREATE TABLE` в базе. Схемы версий 1 и 2 автоматически и транзакционно обновляются до версии 3: товары, склады, остатки, операции, учётные записи, текущие пароли и существующий журнал аудита не удаляются и не сбрасываются. Новая роль не создаёт учётную запись автоматически. Старые одиночные операции остаются отдельными записями: задним числом группировки и накладные не выдумываются. Адреса контрагентов, вес и упаковка прежних товаров остаются пустыми, пока их не заполнят ответственные сотрудники.

В прежней версии могли существовать товары с нулевой ценой или склады с незаполненными полями. Такие записи **сохраняются**, а вверху окна показывается количество требующих исправления товаров и складов. Кладовщик или администратор должен исправить обе цены, администратор — все поля склада. Новые и изменяемые записи обязаны соответствовать правилам; дополнительные SQL-проверки также запрещают сохранение нулевой цены и пустой информации склада. При миграции проверки добавляются без удаления и переписывания исторических несовместимых строк; до их исправления ограничения будут иметь в SQL статус `untrusted`.

Журнал действий начинает собираться с момента обновления: старые складские операции остаются в истории, но события входа и правки за период до внедрения журнала автоматически не восстанавливаются.

## Как начать работу

Новая база изначально **не содержит товаров и остатков**. Старый прототип хранил их только в оперативной памяти и генерировал демо-данные при запуске, поэтому автоматически перенести прежнюю несохранённую историю невозможно.

1. Администратор создаёт менеджера продаж во вкладке «Пользователи».
2. На вкладке **«Организация»** администратор сохраняет наименование, адрес и при наличии УНП грузоотправителя. Наименование и адрес необходимы для проведения реализации.
3. Кладовщик или администратор добавляет товары с единицей измерения и **двумя строго положительными** ценами в BYN; по возможности указывает массу единицы в кг и число единиц на грузовое место.
4. Администратор добавляет склады (название, адрес, ФИО и контакт заведующего обязательны) и контрагентов — поставщиков и покупателей, при наличии с адресом и УНП.
5. На вкладке **«Операции»** кладовщик выбирает **«+ Приход»**, добавляет товары кнопкой **«+ Товар»** и проводит операцию. При перемещении позиции добавляются так же. Состав можно просмотреть, нажав на запись в журнале.
6. Менеджер продаж выбирает **«Реализация»**, добавляет товары, указывает их количество, цену, скидку, НДС, массу и грузовые места; на вкладке **«Накладная ТТН»** выбирает режим НДС и заполняет известные реквизиты перевозки. Затем нажимает **«Провести и создать ТТН»**. Администратор может выполнять все эти действия.
7. Проверьте «Остатки», раскройте фильтры на вкладке «Оборачиваемость», выберите товары и период и нажмите «Применить», затем откройте «Отчёты и диаграммы».

Количество допускает до трёх знаков после запятой, цена — до двух. Суммы по остаткам рассчитываются по **текущим ценам справочника**, а не по историческим ценам операций.

Приход, реализация и перемещение содержат от 1 до 200 товарных позиций. Все позиции записываются в историю и изменяют остатки **в одной транзакции**; при ошибке любой позиции откатываются вся операция, накладная и запись об успешном действии. Расход и перемещение не могут привести к отрицательному остатку. При параллельной работе проведение операций по одному товару сериализуется. Записи справочников, связанные с остатками или историей, удалить нельзя. После первой операции единицу измерения товара изменить нельзя. Не редактируйте остатки и журнал напрямую в SQL: они поддерживаются согласованными через приложение. Проведённые операции в этом учебном варианте не редактируются и не удаляются; дата операции назначается SQL Server при проведении, ввод задним числом не предусмотрен.

## Многотоварные операции и накладная

В журнале **«Операции целиком»** одна строка соответствует одному приходу, перемещению или реализации. Выбор строки показывает внизу все её позиции; транспортная услуга отображается вместе с товарами, но **не изменяет складские остатки**. Вкладка **«По отдельным товарам»** показывает каждое товарное движение отдельно; выбор движения также раскрывает состав всей операции. Фильтр по товару находит всю группу, в которой он встречается, а отдельная вкладка показывает только подходящие движения. Прежние одиночные записи обозначаются `О-`, новые группы — `Г-`. В новых группах сохраняются названия товара, складов, контрагента и имя пользователя на момент проведения; старые записи отображают текущие названия, поскольку их прежние значения неизвестны.

Для каждого товара в реализации цена до скидки предлагается из текущей карточки и может быть изменена. Скидка в процентах применяется к цене единицы; полученная цена и суммы округляются до копеек по правилу `AwayFromZero` (половина — от нуля). Обязательно выберите один из трёх режимов для **каждой реализации**:

- **Цена включает НДС:** цена после скидки умножается на количество; НДС строки = округлить(сумма × ставка / (100 + ставка)), стоимость без НДС = сумма с НДС − НДС.
- **НДС начисляется к цене:** сумма без НДС = округлить(цена после скидки × количество); НДС = округлить(сумма без НДС × ставка / 100), итог = сумма без НДС + НДС.
- **Без НДС:** все ставки очищаются, цены считаются без налога. В двух других режимах пустая ставка у отдельной позиции или транспортной услуги также означает «без НДС»; это **не то же самое**, что ставка 0 %.

Например, одна единица по цене 120 BYN без скидки при ставке 20 % даст: в первом режиме 100 без НДС + 20 НДС = 120 BYN; во втором — 120 + 24 = 144 BYN. В режиме «без НДС» сумма составляет 120 BYN без начисления налога. Ставка допускает до четырёх знаков после запятой, количество — до трёх, скидка и цена — до двух. Программа не определяет налоговый режим или ставку автоматически — их проверяет сотрудник.

Масса в тоннах и число грузовых мест могут быть введены вручную или предложены по карточке товара: `количество × масса единицы в кг / 1000`, число мест — округление количества вверх по упаковке. Кнопка в позиции повторно подставляет оба значения из карточки. Если значения отсутствуют хотя бы у одного товара, соответствующий общий итог остаётся пустым; количество не суммируется между разными единицами. Неизвестные реквизиты не заменяются вымышленными значениями.

Номер накладной предварительно предлагается автоматически; для своего номера снимите флажок автономера и отредактируйте поле. Серия вводится при наличии и может быть пустой. Автономер выделяется на сервере при проведении и может отличаться от предварительного при параллельной работе или совпадении с ручным номером. Пара «серия + номер» уникальна в базе; повтор уже занятого номера отменяет операцию целиком. Внутренний автономер **не является номером защищённого бланка**.

При успешной реализации в SQL сохраняется снимок всех реквизитов, цен, налога и строк, а редактируемый Word-файл создаётся в `%LOCALAPPDATA%\WarehouseCourse\Invoices\<идентификатор_подключения>`. Точный путь появится в сообщении после проведения. Файл с таким именем автоматически не перезаписывается. Если папка недоступна или файл уже существует, продажа остаётся проведённой: **не проводите её повторно**. Выберите операцию в журнале и нажмите **«Сохранить накладную DOCX…»**. Восстановление использует сохранённый снимок, а не текущие карточки, и не включает изменения, сделанные вручную в другом DOCX; храните отредактированные файлы отдельно.

**Правовой предел:** создаётся учебный редактируемый макет по присланному образцу (шапка и товарный раздел), а не защищённый бланк или подтверждённая официальная электронная ТТН-1. Полнота обязательных реквизитов, в том числе подписей, доверенности, пломбы и разделов II–III, здесь не обеспечивается. Перед реальным документооборотом проверьте требования организации и действующую форму/инструкцию по [постановлению Минфина РБ № 58](https://pravo.by/document/?guid=3871&p0=W21631227); при необходимости используйте установленный защищённый бланк. DOCX сам по себе не подтверждает юридическую пригодность накладной.

## Фильтры и отчёты

Фильтры на каждой вкладке изначально свёрнуты. Нажмите **«Фильтры»**, чтобы открыть или закрыть их. После изменения параметров в кнопке **«Применить»** появляются две стрелки обновления, а заголовок фильтров сообщает о неприменённых изменениях. Таблица продолжает показывать прежний результат до успешного применения. Если вернуть поля к последним применённым значениям, значок исчезнет. При ошибке ввода старый результат не заменяется. Клавиша Enter в поле поиска тоже применяет фильтр.

- **Номенклатура, склады, контрагенты, пользователи и журнал:** текстовый поиск по соответствующим полям.
- **Операции:** дата и необязательное время `ЧЧ:ММ` от/до, тип, товар, склад отправления или назначения, контрагент и текстовый поиск. Групповой поиск находит операцию по любому её товару; для новых операций ищется также сохранённое на момент проведения наименование. «Сбросить» очищает условия и обновляет таблицу.
- **Остатки:** склад, товар, минимальное количество, поиск, нулевые остатки и период **последнего движения** по сочетанию товара и склада. Само количество — остаток на текущий момент, а не остаток на историческую дату. Нулевые показываются только для сочетаний товара и склада, по которым были движения.
- **Время:** начало включается. Если время окончания указано, включается вся указанная минута; если время не указано, включается весь конечный день. Времена относятся к часовому поясу SQL Server.
- **Оборачиваемость:** отметьте товары, задайте даты/время и при необходимости склад. Поиск внутри списка товаров скрывает неподходящие строки, но не снимает ранее поставленные отметки. Можно выбрать или снять все **видимые** позиции. «Сбросить» возвращает исходные параметры; затем нажмите «Применить» для пересчёта.
- **Отчёты:** диаграмма закупочной стоимости по складам и диаграмма оборачиваемости показываются в приложении. Отчёт по остаткам использует применённый фильтр «Остатков», отчёт по оборачиваемости — последний расчёт. Пока изменённые параметры не применены, формирование отчёта по ним заблокировано. Сохранение в `.txt` сохраняет только текст, не диаграмму.

## Журнал действий и проверка файла

Во вкладке **«Журнал действий»** показаны события из SQL: время, логин, имя и роль на момент действия, объект и подробности изменения (включая значения до и после, где они применимы). Приход, реализация и перемещение содержат маршруты, позиции, количества и остатки до/после; событие реализации включает снимок накладной. Поскольку журнал может содержать реквизиты и адреса, доступ к файлу и резервным копиям следует ограничить. Записываются успешные и неуспешные входы, изменения справочников, операции, изменения паролей и управление аккаунтами. Пароли и их хеши в журнал **не записываются**. Просмотры и изменение фильтров не журналируются. Вкладка и сведения доступны только для чтения; функции редактирования файла в программе нет.

При каждом штатном изменении событие в `dbo.AuditEvents` фиксируется **в той же SQL-транзакции**, что и данные; неудачные или откатившиеся изменения не создают запись об успешном действии. После фиксации приложение сверяет и дописывает текстовый файл JSONL. Путь к нему показан на вкладке и обычно находится в `%LOCALAPPDATA%\WarehouseCourse\Audit\audit-<идентификатор>.jsonl`. У каждого профиля Windows и подключения к базе свой локальный поток и файл; SQL показывает события всех потоков. Смена имени сервера в настройках может создать другой локальный поток. Чтобы проверить файл другого компьютера или профиля Windows, выполните проверку в том профиле, где файл создавался.

Кнопка **«Проверить файл»**, запуск, штатные действия и периодическая проверка во время работы сопоставляют файл текущего потока побайтово с независимой копией событий и контрольной точкой в SQL. При несовпадении, усечении, лишних байтах или исчезновении ранее записанного файла вверху окна появляется предупреждение **«РАСХОЖДЕНИЕ»**. Программа не перезаписывает подозрительный файл; новые изменения продолжают фиксироваться в SQL. Ошибка доступа к файлу тоже явно показывается: данные, уже сохранённые в SQL, не отменяются и их не нужно вводить повторно. Если запись файла была прервана до фиксации контрольной точки, при следующей успешной проверке ещё не записанные SQL-события дописываются. Повреждение внутри записи после сбоя может, как и вмешательство, вызвать предупреждение.

При предупреждении сохраните копии подозрительного файла и базы, разберите инцидент и восстановите достоверный файл из проверенной резервной копии по тому же пути. Нажмите «Проверить файл»: если сохранённая часть совпадает с SQL и содержит подтверждённые ранее записи, программа допишет ожидающие события. При невозможности восстановить файл обратитесь к администратору БД; не удаляйте и не правьте доказательства, чтобы скрыть предупреждение.

**Границы проверки:** совпадение означает лишь, что проверенный файл соответствует доступному SQL-эталону. Сверка не устанавливает личность изменившего файл и сама по себе не отличает фальсификацию от повреждения или некоторых сбоев. Администратор компьютера может изменить локальный файл; администратор SQL Server может изменить и сам эталон или данные в обход приложения. Согласованная подмена обоих хранилищ может остаться незамеченной, а прямые изменения SQL не становятся событиями приложения. Для более надёжного аудита нужны отдельные ограниченные права и внешнее независимое неизменяемое хранилище/SQL Server Audit или SIEM.

## Формула оборачиваемости

Для каждого выбранного товара берётся вся история до конца периода, в том числе движения до начала периода, чтобы получить начальный остаток. Средний запас рассчитывается как **взвешенный по времени остаток**: каждому значению остатка соответствует длительность, в течение которой он не менялся. Реализация учитывается как отгруженное количество. Для конкретного склада учитываются также входящие и исходящие перемещения; при анализе всех складов перемещение между ними не меняет общий запас.

- `коэффициент = отгруженное количество / средний запас`;
- `дней на оборот = фактическая продолжительность периода в днях / коэффициент`.

Например, при запасе 10 единиц в течение первого дня и 6 единиц в течение второго, отгрузке 4 единиц средний запас равен 8, коэффициент — 0,5, а срок одного оборота — 4 дня. Если средний запас равен нулю, коэффициент и дни не определены и показываются как `—`; если отгрузок не было при положительном запасе, коэффициент равен 0, а срок не определён. Для сегодняшней даты расчёт ограничивается текущим временем сервера. Статусы являются условными: от 3 оборотов — «Высокая», от 1 до 3 — «Нормальная», больше 0 и меньше 1 — «Низкая»; эти пороги не нормализуются на длину периода. При выборе длинного периода, большую часть которого товара ещё не было на складе, средний запас может быть очень малым, а коэффициент — большим.

## Структура проекта

- `kursa/` — WPF-окна, вкладки, диалоги, стили и локальные настройки подключения.
- `Warehouse.Core/Models/` — модели, фильтры и результаты.
- `Warehouse.Core/Data/` — SQL-подключение, версия схемы, запросы, транзакции, управление пользователями и журнал; SQL-схема также доступна в `Schema.sql`.
- `Warehouse.Core/Services/` — проверка ввода, пароли, оборачиваемость, расчёт НДС и запись DOCX.
- `Warehouse.Tests/` — модульные тесты формул, ввода, прав и структуры DOCX, включая проверку Open XML.
- `tests/WpfSmoke/` — проверка WPF-фильтров, прав и форм без SQL; дополнительно при заданных тестовых параметрах SQL проверяется оформление многотоварной реализации через окна и восстановление после ошибки DOCX. Запускается в Windows.
- `tests/SqlSmoke/` — интеграционная проверка на отдельных временных базах SQL Server, в том числе групп, конкурентных изменений, накладных, миграций с версий 1 и 2 и сверки журнала.

SQL Server хранит справочники, пользователей, историю операций, текущие остатки и эталон событий аудита. Внешние ключи и проверки на уровне БД дополняют проверки приложения. При обнаружении несовместимой версии схемы или чужих таблиц с конфликтующими именами приложение не удаляет их и сообщает об ошибке. Для резервного копирования используйте средства SQL Server / SSMS и проверяйте восстановление копии. Файл аудита также копируйте и храните отдельно от рабочего компьютера.

## Проверки разработчика

```powershell
dotnet build kursa.sln -c Release
dotnet test Warehouse.Tests/Warehouse.Tests.csproj -c Release
dotnet run --project tests/WpfSmoke/WpfSmoke.csproj -c Release
```

Для SQL-интеграционного теста нужен **отдельный тестовый экземпляр** с SQL-аутентификацией и правом создавать/удалять тестовые базы. Тест создаёт базы со случайными именами `WarehouseSmoke_*` и удаляет их после завершения. Не используйте рабочий сервер с важными данными:

```powershell
$env:WAREHOUSE_TEST_SERVER = 'localhost'
$env:WAREHOUSE_TEST_USER = 'имя_тестового_sql_пользователя'
$env:WAREHOUSE_TEST_PASSWORD = 'пароль_тестового_sql_пользователя'
dotnet run --project tests/SqlSmoke/SqlSmoke.csproj -c Release
Remove-Item Env:WAREHOUSE_TEST_PASSWORD
```

Необязательный тест полного сценария WPF также создаёт и удаляет **случайную временную базу** с именем `WarehouseWpfSmoke_*`; нужны тот же отдельный тестовый сервер и права создания/удаления баз. Он не проверяет вход через окно логина:

```powershell
$env:WAREHOUSE_WPF_TEST_SERVER = 'localhost'
$env:WAREHOUSE_WPF_TEST_USER = 'имя_тестового_sql_пользователя'
$env:WAREHOUSE_WPF_TEST_PASSWORD = 'пароль_тестового_sql_пользователя'
dotnet run --project tests/WpfSmoke/WpfSmoke.csproj -c Release
Remove-Item Env:WAREHOUSE_WPF_TEST_PASSWORD
```

На Linux можно проверить компиляцию WPF с `-p:EnableWindowsTargeting=true`, однако для обычного запуска и проверки интерфейса требуется Windows.
